# Agent规划：状态空间搜索、随机控制与可验证执行

## 从一个需要多个步骤的实际任务开始

用户提出：“检查代码仓库中的身份认证缺陷，确认问题后修改代码，运行测试并提交报告。”

这个目标不能直接视为一次文本生成。完整任务需要至少完成：确定检查范围、读取必要文件、识别缺陷、产生修复方案、取得写入授权、应用修改、运行验证和形成报告。每一步可能失败，而且一些操作具有不可逆的外部副作用。

规划问题的核心是：**给定当前状态、目标条件、可用行动及约束，计算一组预期能够达到目标的行动，并在执行后根据实际结果重新判断。**

### 什么是状态

为了使问题可计算，定义状态集合 $\mathcal S$。例如：

$$s=(\text{仓库版本},\text{已读取文件},\text{测试状态},\text{剩余预算}).$$

状态是对系统执行所需信息的数学抽象，不等于模型自述“我目前理解了什么”。状态中没有保存的信息，可能导致规划器做出与真实环境不一致的判断。

### 什么是行动

行动集合 $\mathcal A(s)$ 表示当前状态允许执行的操作，例如只读检索、运行受控测试、提交待审核补丁。每个行动都有前置条件、成本和可能产生的状态变化。

如果当前用户没有写入权限，写入操作即使能够被语言模型提出，也不应被执行器视为合法行动。**合法性由外部授权记录决定，不由模型生成的声明决定。**

### 什么是目标

目标是状态上的可检查条件：

$$G(s)\in\{0,1\}.$$

例如：

- 指定的测试集合已经运行且通过；
- 修改只影响获授权的文件；
- 原缺陷被独立检查器确认消除；
- 报告包含真实代码版本和可核查证据。

如果仅把“模型回复了任务已完成”作为目标，就可能在没有执行实际检查的情况下错误地终止任务。

## 确定性规划：先从最短路径开始

### 把任务表示成图

设状态为图的顶点、行动为有向边。行动 $a:s\to s'$ 具有非负成本 $c(s,a)$。

例如：

~~~text
开始 --成本1--> 初查 --成本10--> 完成
  |               |
 成本3           成本1
  |               |
  v               v
 审核 --成本2--> 完成
~~~

另有从初查到审核的成本1边。图中最少边数的路径不一定具有最低总成本。

### BFS适用于什么情况

广度优先搜索（BFS）按照边数逐层搜索。在所有边成本相同的无权图中，第一次到达目标可得到最少边数路径。

但若上例成本不同，BFS可能找到“开始→初查→完成”，只有两步却需要成本11。另一条“开始→初查→审核→完成”有三步、总成本4。

BFS保证的是**最少边数**，不是任意加权图中的最小成本。

### Dijkstra为什么能处理不同成本

在边成本非负时，Dijkstra算法始终扩展当前已知累计成本最小的状态，并通过松弛更新相邻状态：

$$
g(s')\leftarrow
\min\{g(s'),\,g(s)+c(s,a)\}.
$$

当目标首次以当前最小成本出队时，能够得到最小累计成本。若存在负权边，普通Dijkstra的保证不再成立。

实际Agent任务中，边成本可以是执行时间、API费用、人工审核成本或复合指标。但把多个不同单位直接相加，必须先说明权重与量纲，不能只用一个随意的“综合成本”掩盖风险。

## A*搜索：把已发生的成本与剩余估计结合

### 评价函数从哪里来

Dijkstra不利用与目标有关的额外信息。A*为每个状态构造：

$$
f(s)=g(s)+h(s),
$$

其中：

- $g(s)$：从起点到当前状态已经发生的路径成本；
- $h(s)$：从当前状态到目标的剩余成本估计。

A*优先扩展 $f(s)$ 较小的状态。

### 可采纳启发式

若真实最优剩余成本为 $h^*(s)$，启发式满足：

$$
0\le h(s)\le h^*(s),
$$

则称其为可采纳（admissible）。它不会高估剩余成本。

对于前面的图，取：

$$h(\text{目标})=0,\quad
h(\text{审核})=2,\quad
h(\text{初查})=3,\quad
h(\text{开始})=4.$$

这些数字恰好是该图上的真实剩余最优成本，因此属于可采纳启发式。

### 一致性使搜索更容易正确实现

更强的条件是：对于每条边 $s\to s'$，

$$
h(s)\le c(s,a)+h(s').
$$

这称为一致性（consistent）。非负成本加上一致启发式，使常见的图搜索实现能够在状态从优先队列正式取出后安全地标记为已完成。

若启发式只有可采纳性、未满足一致性，实现可能需要重新打开此前扩展过的状态，不能简单照搬不重开节点的版本。

### 为什么“模型觉得距离目标很近”不能直接用于最优性证明

大模型可以估计一个任务还需要多少步，但这种估计未必是可采纳的，它可能大幅高估实际剩余成本。

因此如果使用模型启发式，就不能未经测试宣称A*依然保证最优。可以采用保守下界、独立计算的松弛问题或仅将模型估计用于排序而不做最优性保证。

## 任务依赖图与规划顺序

### 不是所有任务都能任意交换

假设必须先读取文件，再形成补丁，然后运行测试。依赖关系可以写为：

$$
\text{读取}\prec\text{修复}\prec\text{验证}.
$$

若存在两个互不依赖的测试，它们可以并发执行；如果两个操作同时写同一个文件，则必须明确版本冲突和写入顺序。

对有向无环图（DAG），可用拓扑排序给出一个满足全部先后约束的执行顺序。若依赖图包含环，例如“A依赖B、B依赖A”，就需要重新定义任务，而不是让执行器无限等待。

### 规划顺序与执行顺序仍有差别

即使拓扑顺序合法，也不代表每个操作都执行成功。实际工具执行可能改变环境、产生新依赖或提前使目标成立。

可靠的执行器每步都会记录：

$$\text{计划动作}\longrightarrow\text{执行结果}\longrightarrow\text{新观测状态}.$$

若实际状态与预期状态不同，就要重新搜索或进入明确的失败处理，而不能沿着过期计划继续执行。

### 计划生成阶段

输入包括目标、当前状态、合法动作、预计成本、权限和资源上限。输出是候选行动序列及其预期前置条件。

规划器可以是确定性搜索算法，也可以调用语言模型生成候选动作。但无论来源如何，候选动作进入执行器前都要通过结构化校验和授权检查。

### 执行阶段

每次执行之前确认当前状态版本仍与计划一致。若其他执行者已经修改状态，应重新获取状态，而不能在陈旧快照上覆盖写入。

对有副作用的工具，还应记录唯一请求ID和外部确认信息。网络超时后，不应简单认为“没有收到成功响应，所以动作没发生”。

### 验证与恢复

成功必须由独立检查器验证。对于代码修复，可以运行原缺陷复现测试、回归测试以及文件差异检查；对于检索问答，可检查证据版本与引用是否成立。

失败后先区分：

1. **可确认未执行**：可以考虑重新规划或按约定重试。
2. **可确认已执行但目标未达成**：需要更新状态、可能执行补救操作。
3. **外部结果未知**：必须先查询外部状态，不应盲目重复写操作。

这三类状态不能全部当作“失败，重试一下”。

## 把A*转换为可运行的搜索程序

### 状态和行动必须是结构化对象

一个简单的规划图可定义为：字典的键是状态，值是可执行行动的列表。每个行动有后继状态、成本与所需权限。例如：

~~~python
graph = {
    "start": [
        ("risk", 1, "read"),
        ("audit", 3, "read"),
    ],
    "risk": [
        ("goal", 10, "deploy"),
        ("audit", 1, "read"),
    ],
    "audit": [
        ("goal", 2, "deploy"),
    ],
    "goal": [],
}
~~~

如果没有deploy权限，则通往goal的边不属于合法行动。规划器不能把“我认为部署很重要”当作绕过权限的理由。

### 最小A*循环

~~~python
from heapq import heappop, heappush

def astar(start, goal, edges, h, permissions):
    frontier = [(h[start], 0, start, [])]
    best = {start: 0}
    while frontier:
        _, cost, state, path = heappop(frontier)
        if cost > best[state]:
            continue
        if state == goal:
            return path, cost
        for nxt, edge_cost, scope in edges[state]:
            if scope not in permissions:
                continue
            if edge_cost < 0:
                raise ValueError("negative edge cost")
            candidate = cost + edge_cost
            if candidate < best.get(nxt, float("inf")):
                best[nxt] = candidate
                heappush(frontier, (
                    candidate + h[nxt], candidate,
                    nxt, path + [nxt]
                ))
    return None
~~~

这段教学代码假设状态可以比较、成本非负，且给定的启发式满足所声称的条件。完整实验另外实现了稳定的优先队列顺序、边校验、失败后阻止重试的动作记录和执行阶段再次检查权限。

### 为什么执行阶段仍须再次检查权限

规划器读到的权限可能已经在执行前被撤销。仅在规划时检查一次，不足以保证真正执行工具时仍有权操作。实际执行器应从可信授权源重新核验动作、资源范围和请求版本，检查通过后才实施具有副作用的操作。


## 行动具有随机结果时怎样计算规划价值

### 确定性图不够用

假设某个检查动作有80%概率立即发现并解决问题，20%概率进入需要额外处理的状态。

在这种情况下，同一个状态执行相同行动，下一状态并不唯一。可用条件分布表示：

$$P(S_{t+1}=s'\mid S_t=s,A_t=a).$$

每个行动可能还有即时随机成本 $C_t$。规划目标之一是寻找使累计成本数学期望最小的行动条件分布或确定性选择规则。

### 用全期望公式建立Bellman递推

对于有限时域、终端成本为0的情形，设 $V_t(s)$ 为时刻 $t$ 处于状态 $s$ 时，后续最小期望成本。

在合法行动集合 $\mathcal A(s)$ 上：

$$
\boxed{
V_t(s)=\min_{a\in\mathcal A(s)}
\left[
c_t(s,a)+
\sum_{s'}P(s'\mid s,a)V_{t+1}(s')
\right].
}
$$

这来自条件期望的线性性、全概率公式和在当前状态下选取最小条件期望成本。这里的 $c_t(s,a)$ 表示已将即时随机成本取条件期望的结果。

如果行动还有安全风险、时间上限或授权约束，不能只优化一个无约束平均成本；应把相关限制明确写入合法行动集合、风险约束或多目标评价中。

### 一道两行动手算题

当前可以选择：

- 稳妥执行：成本5，必定到达终点；
- 尝试快速路径：即时成本1，80%直接成功；20%进入故障恢复状态，后续成本10。

快速路径的期望总成本：

$$1+0.8\times0+0.2\times10=3.$$

只以期望成本为目标时，应选择快速路径（3小于5）。但若不允许出现额外10的故障恢复风险，或必须遵守严格的完成时间要求，选择可能不同。这说明最小期望成本与风险控制是两个问题。

## 状态无法完全观察时怎么办

### 观测不等于真实状态

假设服务器是否已修复是隐藏状态 $S$，只观察到一次健康检查结果 $O$。一次成功的网络响应并不一定意味着全部故障都已经消除。

可以维护关于隐藏状态的条件分布，也称为信念状态：

$$b_t(s)=P(S_t=s\mid O_{0:t},A_{0:t-1}).$$

它是一个概率分布，不是大模型随意填写的“置信度”。

### 从先验推导后验

假设服务器故障先验概率0.1，健康检查告警在真实故障时的概率为0.8，在正常时误报概率为0.05。

观察到告警后的故障概率：

$$
P(F\mid+)=
\frac{0.8\times0.1}
{0.8\times0.1+0.05\times0.9}
=\frac{0.08}{0.125}=0.64.
$$

这表示获得告警证据后，按给定模型故障概率更新为64%，不意味着故障已被确定。是否执行修复，还要结合修复成本、误修风险及进一步检查的价值。

### 贝叶斯状态更新

若行动 $a$ 后产生观测 $o$，先对隐藏状态进行转移预测：

$$\widetilde b_{t+1}(s')
=\sum_sP(s'\mid s,a)b_t(s).$$

再用观测似然更新：

$$
b_{t+1}(s')=
\frac{P(o\mid s',a)\widetilde b_{t+1}(s')}
{\sum_uP(o\mid u,a)\widetilde b_{t+1}(u)}.
$$

这就是部分可观察序列决策中常见的信念状态更新。实际系统中需要估计转移与观测模型，否则得到的概率只是建立在假设上的数值。

## Agent规划的三种实现路径

### 固定工作流

对于步骤明确、不能自由改变顺序的任务，可以采用固定DAG或状态机。优点是容易审计、约束清晰；局限是对未知故障缺少灵活性。

### 基于搜索的规划器

如果行动、状态转移与成本可以列举，就能使用BFS、Dijkstra、A*、动态规划或其他搜索方法。每次扩展动作时，由确定性规则判断前置条件与授权。

这种方式适合有限任务空间、代码构建流水线、明确的运维操作图。空间太大时，需要状态抽象、启发式或候选生成，不能直接枚举所有状态。

### 大模型提出候选动作

当自然语言任务难以直接转成固定图，模型可以负责把目标转成子任务并提出工具候选。但它提出的动作仍需经过类型校验、权限校验、预算检查以及独立验证。

“模型想到了操作”与“系统允许执行操作”是完全不同的事件。模型建议器和工具执行器应分开设计，尤其不能让模型直接修改自己的授权列表或检查器。

实验中，模拟失败被定义为：动作确定没有改变状态。因而可以删除对应可用边并重新搜索。真实网络请求超时时，外部动作可能已经发生，必须先查询执行状态。不能把实验中的“失败无副作用”假设直接用于付款、数据库修改或删除文件。

## 习题与解答

### 练习：BFS与A*可能得到不同路线

图中“开始→初查”成本1，“初查→目标”成本10，“初查→审核”成本1，“审核→目标”成本2。

**解：** BFS按照边数会优先考虑两步路线“开始→初查→目标”，成本11；最小成本路线是“开始→初查→审核→目标”，成本4。BFS的最少边数保证不适用于成本不等的图。

### 练习：启发式可采纳性

一个状态的真实最优剩余成本为7。若启发式分别估计5和9，哪一个可采纳？

**解：** 估计5不高于7，满足可采纳要求；估计9超过真实值，不可采纳。估计5仍需检查图中所有相关边是否满足一致性条件，不能由单点估计直接推出。

### 练习：随机成本

快速路径即时成本1，80%直接成功，20%需要再花10。求期望成本。

**解：** 由全期望公式 $1+0.8\times0+0.2\times10=3$。

### 练习：告警后验

先验故障概率0.1，真实故障告警概率0.8，正常误报概率0.05。

**解：** 告警总概率 $0.8(0.1)+0.05(0.9)=0.125$，故障后验为 $0.08/0.125=0.64$。

1. 设计一个具有写入权限、读权限和审核权限的任务图，说明哪些动作必须被拒绝。
2. 把A*启发式改成故意高估，构造丧失最优性保证的例子。
3. 让两个Agent同时修改状态版本10，检查条件更新能否拒绝陈旧写入。
4. 为重试中的外部操作设置幂等键、最大尝试次数、时间上限和成本上限。
5. 分别用BFS与A*求解同一图，记录扩展状态数量和总成本。
6. 为具有20%失败风险的行动加入“失败概率不得超过5%”的约束，并讨论是否还可选择快速路径。
